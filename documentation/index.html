Referzen

Affiliate and referral program software as a service, built with Next.js 16, React 19 and Tailwind CSS 4. Your customers run their own referral programs with a branded affiliate portal, automatic tracking from Stripe, WooCommerce and Shopify, and payouts in one CSV file. This guide takes you from a fresh clone to a live platform with paying customers.

Quick start: upload the app folder, run npm install and npm run build, start the app, then open your domain in a browser. The web installer does the rest. Then read Background jobs & scheduling (commissions are approved by a background job) and the Merchant guide and Integrations, which you can also share with your customers.

Introduction

Referzen lets you run your own affiliate and referral platform, like Rewardful, FirstPromoter or Tolt. Your customers (merchants) sign up, create a referral program for their SaaS product or online store, set a commission (for example 30 % of every payment for 12 months) and invite affiliates: bloggers, partners, agencies or happy customers who recommend the product.

Every affiliate gets a personal link such as https://acme.com/?ref=jane and a branded portal (/a/<program>) with their link, a link builder, clicks, conversions, earnings, marketing assets and payout details. A tiny script on the merchant's website (rz.js, about 1.4 KB gzipped) remembers the referral in a first-party cookie. When the referred customer pays, Stripe, WooCommerce, Shopify or the merchant's own server reports the payment to Referzen, which credits the right affiliate with a commission. Refunds and disputes reverse the commission automatically. After a hold period (the refund window) commissions are approved, and the merchant pays them in batches with a PayPal Payouts CSV or a bank transfer CSV.

Commissions are single-tier: an affiliate earns on the customers they referred, nothing else. There are no levels, no recruiting bonuses and no commissions on other affiliates' sales.

You earn money with paid plans. Plans limit the number of programs, affiliates and conversions per month, give access to the REST API and remove the “Powered by” line from portals and emails. Your customers pay through Stripe (automatic renewal), PayPal, Razorpay or manual bank transfer.

Words used in this guide: you or the administrator run the platform. Merchants are your customers: they sign up on your platform and create referral programs. Affiliates promote a merchant's program. Referred customers buy from the merchant after clicking an affiliate link. In the examples your platform lives at https://partners.example.com and a merchant's website at https://acme.com.
Referzen does not move money. It calculates what each affiliate has earned and creates the files to pay them, but the merchant sends the money with their own PayPal or bank account and then marks the payout as paid. Referzen never holds, transfers or guarantees funds.

Installation

Pick the guide that matches your hosting. Every method ends with the web installer, and every method needs a way to run background jobs: read Background jobs right after installing.

Install Referzen on its own domain or subdomain, for example https://partners.example.com or https://refer.yourbrand.com. The tracking snippet and every webhook URL contain this address, so changing it later means every merchant must update the snippet on their website and the webhook URL in Stripe, WooCommerce or Shopify. Some privacy blocklists block hostnames that contain words like affiliate or track; a neutral name is safer.

cPanel / shared hosting (Setup Node.js App)

  1. In cPanel open MySQL® Databases. Create a database and a user, then add the user to the database with All privileges. Write down the database name, username and password.
  2. Create the subdomain (e.g. partners.example.com) in Domains and turn on SSL/TLS Status → Run AutoSSL so it has HTTPS.
  3. Open File Manager and upload referzen.zip (the app folder of the repository, renamed to referzen and zipped) to your home folder, e.g. /home/youruser/referzen, and extract it. Do not put it inside public_html.
  4. Open Setup Node.js App → Create Application:
    • Node.js version: the newest available (22.x recommended)
    • Application mode: Production
    • Application root: referzen
    • Application URL: your domain or subdomain
    • Application startup file: server.js
    Click Create.
  5. Click Run NPM Install and wait until it finishes.
  6. Copy the command shown at the top of the page (it looks like source /home/youruser/nodevenv/referzen/22/bin/activate && cd /home/youruser/referzen). Open Terminal in cPanel, paste it, then run: 
    npm run build
    The build takes 1–4 minutes. It first prints [tracker] public/rz.js … B gzip (the tracking script), then builds the app.
  7. Back in Setup Node.js App, click Restart. Open your domain: you will see the installer.
  8. After installing, add the cron job from Admin → System (see Cron URL). On cPanel this is strongly recommended: Passenger stops idle apps, and lazy mode only runs while there is activity.

server.js starts the built Next.js app, which serves everything: pages, the portals, the API, the webhook URLs and the files in public, including /rz.js. You don't need to copy anything into public_html.

If the build stops with “JavaScript heap out of memory” your plan limits memory. Build on your own computer instead (npm install && npm run build), then upload the whole folder including the .next folder and public/rz.js, and only run “Run NPM Install” + “Restart” on the server.

VPS (Ubuntu) with PM2 and Nginx

  1. Install Node.js 22, Nginx and PM2: 
    curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs nginx
sudo npm install -g pm2
  2. Install MySQL (or use SQLite and skip this step): 
    sudo apt install -y mysql-server
sudo mysql -e "CREATE DATABASE referzen CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'referzen'@'localhost' IDENTIFIED BY 'choose-a-strong-password';
GRANT ALL PRIVILEGES ON referzen.* TO 'referzen'@'localhost'; FLUSH PRIVILEGES;"
  3. Upload the app folder to /var/www/referzen, then build: 
    cd /var/www/referzen
npm ci
npm run build
  4. Choose a cron secret and start the app and the worker with PM2. ecosystem.config.cjs starts two processes: referzen (the web app) and referzen-worker (runs the background jobs every 15 seconds). Both get the same CRON_SECRET: 
    export CRON_SECRET="$(openssl rand -hex 24)"
echo "$CRON_SECRET"          # keep a copy
pm2 start ecosystem.config.cjs
pm2 save && pm2 startup

    Always set your own CRON_SECRET before pm2 start. Without it the worker can't run jobs (PM2 prints a warning and the worker exits), and a CRON_SECRET line in .env.local is only seen by the worker, not by the app. Export the variable before pm2 start (as above) or write your secret into ecosystem.config.cjs. Use at least 12 random characters: the app ignores shorter values and the example value change-me-to-a-long-random-string. After changing it run pm2 restart ecosystem.config.cjs --update-env.

  5. Create /etc/nginx/sites-available/referzen: 
    server {
    listen 80;
    server_name partners.example.com;
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
    X-Forwarded-For is important: Referzen uses the visitor's IP address (only in memory) to recognise repeated clicks of the same visitor and for rate limits. Enable the site and add a free SSL certificate: 
    sudo ln -s /etc/nginx/sites-available/referzen /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d partners.example.com
  6. Open https://partners.example.com to run the installer. Afterwards, Admin → System → Scheduler should show Running with the source worker within a minute.
Keep instances: 1 for the web app in ecosystem.config.cjs: rate limits and some caches are kept per process. One Node.js process handles a lot of clicks and webhooks. The worker calls http://localhost:3000 by default; set WORKER_URL if the app listens elsewhere.

Docker

The app folder includes a Dockerfile and a docker-compose.yml with three services: app (the web app), worker (runs background jobs every 15 seconds) and db (MySQL 8.4). First create a file named .env next to docker-compose.yml with your own secret:

CRON_SECRET=paste-a-long-random-string-here

Then start everything:

cd referzen
docker compose up -d --build

Open http://your-server:3000. In the installer choose MySQL with host db, port 3306, database referzen, user referzen, password referzen (change these and MYSQL_ROOT_PASSWORD in docker-compose.yml first). The storage folder is kept in a Docker volume. Put Nginx, Caddy or Traefik with HTTPS in front of port 3000, and make sure it sends X-Forwarded-For.

docker-compose.yml refuses to start until CRON_SECRET is set in the .env file next to it (at least 12 random characters). The included .dockerignore keeps local node_modules, .next and storage folders out of the image.

Without Compose:

docker build -t referzen .
docker network create referzen-net
docker run -d --name referzen --network referzen-net -p 3000:3000 \
  -e CRON_SECRET=your-secret -v referzen-storage:/app/storage referzen
docker run -d --name referzen-worker --network referzen-net \
  -e WORKER_URL=http://referzen:3000 -e CRON_SECRET=your-secret referzen node scripts/worker.mjs

Vercel (with a cloud MySQL database)

Vercel has no permanent disk, so the web installer and SQLite can't be used there. Instead, Referzen is configured with environment variables and a cloud MySQL-compatible database such as TiDB Cloud Serverless (free tier), Aiven or PlanetScale.

  1. Create a database. In TiDB Cloud: create a Serverless cluster in the region closest to your Vercel functions, open Connect, generate a password and note the host, port (4000), user and password. In the SQL editor run CREATE DATABASE referzen;
  2. Fork this repository on GitHub (or push your copy to your own repository).
  3. In Vercel click Add New → Project, import the repository and set Root Directory to app (the folder that contains package.json). Keep the default build command (npm run build): it also builds rz.js.
  4. Add these Environment Variables: 
    DB_DRIVER=mysql
DB_HOST=gateway01.ap-southeast-1.prod.aws.tidbcloud.com
DB_PORT=4000
DB_USER=xxxxxxxx.root
DB_PASSWORD=your-password
DB_NAME=referzen
DB_SSL=true
APP_INSTALLED=true
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD=a-strong-password
ADMIN_NAME=Your Name
SITE_URL=https://partners.example.com
CRON_SECRET=a-long-random-string
    Instead of the DB_* variables you can set one DATABASE_URL=mysql://user:password@host:4000/referzen?ssl=true.
  5. Click Deploy. Tables are created automatically on the first visit and the administrator account is created from ADMIN_EMAIL / ADMIN_PASSWORD.
  6. Add your domain in Settings → Domains, and set the same address in Admin → Settings → General → Site URL.
  7. In Vercel open Settings → Functions and choose the region closest to your database.
  8. Set up the scheduler as described in Vercel & serverless. This step is not optional on Vercel: without it, commissions are never approved.

Vercel is fine for a demo or a small platform. Keep in mind:

  • There is no worker process, so background jobs depend on an external cron service.
  • Uploaded files (logos, banners) are not kept (no permanent disk). Paste image URLs instead of uploading.
  • Rate limits are kept per serverless instance.

Local computer (for testing or customising)

cd referzen
npm install
npm run dev

Open http://localhost:3000 and choose SQLite in the installer. Lazy mode is on by default, so background jobs run while you click around. To run them without visiting pages, start the worker in a second terminal (copy the secret from Admin → System → Scheduler):

CRON_SECRET=the-secret-from-admin npm run worker

On Windows PowerShell: $env:CRON_SECRET="the-secret"; npm run worker.

To test the tracking script on your computer, create a program with the website localhost, or switch on Count clicks from localhost in the program's tracking settings. Then open a local page with the snippet and ?ref=CODE in the address. See Troubleshooting.

Web installer

  1. Requirements – checks the Node.js version and that storage is writable.
  2. Database – choose MySQL/MariaDB (host, port, database, user, password, and Use SSL for cloud databases such as TiDB Cloud, Aiven or DigitalOcean) or SQLite. Click Test connection, then continue.
  3. Site & admin – enter your platform name, the full site URL (e.g. https://partners.example.com) and the administrator account. Click Install now.

The installer creates all tables and indexes, the three default plans (Free, Pro, Agency), the default content pages (such as the Privacy policy and Terms of service) and starter blog posts. It writes storage/config.json and locks itself (storage/installed.lock). Sign in at /login. The admin panel is at /admin, the merchant dashboard at /dashboard, affiliate portals at /a/<slug>.

To run the installer again (e.g. to switch databases), delete storage/installed.lock and storage/config.json and restart the app. Existing data in the old database is not deleted.

First steps after installing

The admin dashboard shows a Finish setting up checklist. In short:

  1. Settings → General: check the Site URL. It must be your public https:// address: the tracking snippet, webhook URLs, portal links in emails and the cron URL are built from it. Add your brand name and logo.
  2. Admin → System → Scheduler: set up the cron URL or the worker (see Background jobs) and check that the badge says Running.
  3. Settings → Email: configure SMTP. Affiliate invitations, password resets, commission emails and digests need it.
  4. Settings → Referrals: the default hold period for new programs, the branding line in portals and emails, and the program shown on your home page.
  5. Plans: adjust prices and limits. Settings → Payments: connect at least one payment gateway.
  6. Open /dashboard and create your own referral program for your platform (your merchants can become your affiliates). You can feature its portal on your home page (Settings → Referrals → Program to feature on your home page).

How referral tracking works

Every sale passes through the same steps. Knowing them makes the rest of this guide (and most support questions) easy.

1. Click→2. Lead (optional)→3. Conversion→4. Pending (hold)→5. Approved→6. Paid
  1. Click. A visitor opens an affiliate link, e.g. https://acme.com/pricing?ref=jane. The tracking script rz.js on acme.com sends the click to Referzen (POST /api/click). If jane is an approved affiliate of an active program, Referzen records the click and answers with a referral token (24 random letters and digits). The script stores it in the first-party cookie rz_ref on acme.com for the program's cookie duration (default 60 days), with a copy in localStorage.
  2. Lead (optional). When the visitor signs up, the merchant can tell Referzen who they are (email and/or customer id) with referzen.signup(), the REST API or a generic webhook. Later payments of that customer are then credited even if the cookie is gone.
  3. Conversion. The visitor pays. Stripe, WooCommerce, Shopify or the merchant's server reports the payment to the program's webhook URL (or the REST API) together with the referral token (Stripe client_reference_id, order meta, cart attribute…). Referzen finds the affiliate, computes the commission and records a conversion. Repeating the same order id never creates a second conversion.
  4. Pending. New conversions are pending during the program's refund window (hold period, default 30 days). A refund of at least half of the payment, a cancelled order or a dispute reverses the conversion automatically.
  5. Approved. When the hold period has passed, the approve-commissions background job approves the conversion. Conversions with a fraud flag wait for the merchant's review instead (even with a 0-day hold). The merchant can also approve a conversion by hand at any time.
  6. Paid. Approved commissions form the affiliate's due balance (approved means payable). Once it reaches the program's minimum payout, the merchant includes it in a payout batch, pays it outside Referzen (PayPal Payouts CSV, bank transfer) and marks it as paid. A refund after the payout is deducted from the affiliate's next payout.

Subscription renewals of a referred customer are credited automatically (step 3 without a new click), as long as the program's recurring rule allows it. See Commission rules.

Background jobs & scheduling

Clicks and webhooks are processed the moment they arrive; that never depends on the scheduler. But several important things happen in the background, and something must start them. Read this chapter before you invite merchants: without background jobs, pending commissions are never approved and nobody can be paid.

The jobs

A tick runs these jobs one after the other, within a time budget. Each job does a small slice of work and remembers when it should run again, so ticks every 15 seconds are cheap. Whatever doesn't fit is picked up by the next tick. A lock in the database makes sure two ticks never run at the same time.

JobWhat it doesHow often
approve-commissionsPending conversions whose hold period (the program's refund window, counted from the payment date) has ended become approved (and payable). Conversions flagged self-referral, same device, repeat customer or other currency stay pending for the merchant's review (see Fraud flags). Up to 1,000 per tick.Every 10 minutes (sooner while there is a backlog)
click-rollupsSummarises every finished UTC day of clicks into daily totals per program and affiliate (10 minutes after midnight UTC), then deletes raw clicks older than 90 days (only days that are summarised).Every 10 minutes
notificationsSends the daily digest to merchants (yesterday's new affiliates, conversions, reversals and the balance ready to pay) and the weekly summary to affiliates (last Monday–Sunday). Up to 40 emails per tick. Waits while SMTP isn't configured.Every 15 minutes

The cron secret

The cron URL and the worker are protected by a secret:

  • If the environment variable CRON_SECRET is set (at least 12 characters, not the example value), that value is the secret.
  • Otherwise Referzen creates a random secret the first time it is needed and stores it in the database.

To see it, open Admin → System. The Scheduler card shows the complete Cron URL (with a Copy button) and a ready-made cron line. Click New secret to replace a stored secret, e.g. if it leaked; the old URL stops working immediately, so update your cron job and worker. The button is hidden while the secret comes from CRON_SECRET: change the environment variable instead and restart.

The secret can be sent in two ways:

curl -fsS "https://partners.example.com/api/cron/tick?key=YOUR-SECRET"
curl -fsS -H "Authorization: Bearer YOUR-SECRET" https://partners.example.com/api/cron/tick

GET and POST both work. A correct call answers with a JSON summary, for example {"source":"cron","startedAt":"…","jobs":{"approve-commissions":3,"click-rollups":120,"notifications":1,"usage":0,"housekeeping":0},"failed":[],"skipped":[],"durationMs":840,"skippedLocked":false}. The numbers are the items each job handled (conversions approved, clicks summarised, emails sent, usage notices, rows cleaned up). A wrong or missing secret answers 401. More than 30 calls per minute from one IP address answer 429.

Lazy mode (default, no setup)

With Admin → Settings → Referrals → Run background jobs on visits switched on, the platform runs a tick after it has answered a page request, a click or a webhook, whenever no tick ran during the last minute. The visitor never waits. A lazy tick has an 8-second time budget, and each server process tries at most once every 15 seconds.

Lazy mode only works while there is activity: people opening your platform's pages or portals, clicks, or webhooks. At night, or on a new platform, nothing may run (e.g. a commission whose hold ended stays pending, and the daily digest is late). On cPanel, Passenger also stops the app after a period without requests. Use it to get started, then add the cron URL or the worker. You can leave lazy mode on as a backup: it does nothing while cron or the worker keep ticks fresh.

Cron URL

Open the URL every minute (every 5 minutes is also fine) from any scheduler. Copy the exact URL from Admin → System → Scheduler.

  1. Open Cron Jobs in cPanel.
  2. Under Add New Cron Job choose Once Per Minute (* * * * *) (or Once Per Five Minutes).

Worker (every 15 seconds)

The worker is a tiny Node.js script (scripts/worker.mjs) that calls the cron URL of the running app every 15 seconds. It needs the app to be running and the same secret.

CRON_SECRET=YOUR-SECRET npm run worker
VariableMeaning

  • Docker: the worker service in docker-compose.yml runs it with WORKER_URL=http://app:3000. Logs: docker compose logs -f worker.
  • systemd: create a service with ExecStart=/usr/bin/node /var/www/referzen/scripts/worker.mjs, WorkingDirectory=/var/www/referzen, Environment=CRON_SECRET=… and Restart=always.

  • With a fixed commission (already in the program currency) the commission is kept; the merchant only approves it.
  • Revenue totals (overview, top affiliates, digests, Admin → Programs) leave these sales out, because their amounts can't be added to the program currency.

Cookie window & attribution order

The cookie duration (attribution window, 1–365 days, default 60) is how long a referral is remembered after a click. A payment is credited to an affiliate when one of these matches, checked in this order (last click wins: a newer click of another affiliate replaces the cookie):

  1. Referral token (the rz_ref cookie, passed as Stripe client_reference_id or metadata, WooCommerce order meta, Shopify cart attribute, or referral in the API) whose click (or lead) happened inside the cookie window. Once a referral has converted, its token keeps working for that customer without a window.
  2. Affiliate code (affiliate_code in the REST API, affiliate in the generic webhook, or ?ref=CODE on the landing page of a Shopify order).
  3. The subscription or customer of an earlier conversion (renewals and repeat orders: no window; the recurring rule decides whether they earn).
  4. A lead with the same customer id, then with the same email, created inside the cookie window (or already converted).
  5. A coupon code used for the order that the merchant assigned to an affiliate (on the affiliate's page; matched case-insensitively, no window). Read from WooCommerce coupon_lines, Shopify discount_codes, coupon / coupon_code / coupons in the generic webhook, coupon in the REST API, and Stripe metadata.coupon (see Stripe).

Anything else is not referred: the webhook answers 200 with "status": "ignored" and the reason, and nothing is recorded. Only approved affiliates earn: links of pending or blocked affiliates don't set a cookie, and payments referred by an affiliate who has been blocked since are ignored.

The window is checked against the payment date. A click on 1 March with a 60-day cookie covers payments until 30 April. The cookie itself also expires in the visitor's browser after the window.

Hold period & approvals

The refund window (hold period, 0–365 days; the default for new programs is set in Admin → Settings → Referrals, 30 days out of the box) protects the merchant against refunds: new conversions stay pending for that many days after the payment. When it has passed, the approve-commissions job (see Background jobs) makes them approved, and they count towards the affiliate's due balance. Approved means payable: the job only approves after the hold period, and a conversion the merchant approves by hand is payable at once.

StatusMeaning
PendingInside the refund window, or flagged and waiting for review.

The commission is payable right away. A sale in another currency is approved with a commission entered in the program currency (see sales in another currency).
  • Reverse with a reason (Refunded, Chargeback, Against the program terms, Test order, or your own text, shown to the affiliate) and optionally an email to the affiliate. Works for pending, approved and paid conversions. A reversed conversion that was in an unpaid payout is taken out of it; a paid one is deducted from the affiliate's next payout.
  • Reopen puts an approved or reversed conversion that is not in a payout back to pending (a conversion reversed after its payout can't be reopened).
  • With a refund window of 0 days, conversions are approved the moment they are recorded, except flagged ones, which still wait for review.
Refunds after a payout. A refund or dispute in Stripe, WooCommerce or Shopify (or a reversal by hand or through the API) after the commission was paid out still reverses the conversion. Its commission is recorded as a negative adjustment and deducted from the affiliate's next payout batch: the Payouts page shows the deduction, the full payout list CSV has an Adjustments column, and the PayPal and bank files pay the net amount. The affiliate sees the adjustment in their portal. If the affiliate earns nothing more, the negative balance simply waits; settle it with them according to your program terms.

Fraud flags & review

Referzen checks every click and conversion:

  • Bots, link previews and browser prefetches are dropped (the isbot list, empty or very short user agents, Purpose: prefetch headers). They never become clicks.
  • Duplicate clicks: the same visitor clicking the same affiliate's link again within 30 minutes is recorded as a duplicate (it counts as a click but not as a unique click) and keeps the same referral token.
  • Clicks are only accepted from pages on the program's website, and only for approved affiliates of an active program.

Conversions can carry these flags, shown as badges on the Conversions page with an explanation:

When flagged conversions wait, the Conversions page shows “N flagged conversions need your review” with a Review now link (the Flagged only filter). Admin → System shows how many conversions are held platform-wide.

Payouts

Referzen does not send money. It works out who is owed what and creates the files; the merchant pays with their own PayPal or bank account, then marks the payout as paid in Referzen. Approved commissions are payable: the approve-commissions job approves them once the refund window has passed, and commissions the merchant approves by hand are payable at once. Creating a batch

  1. In Ready to pay, select the affiliates to pay (all are selected by default), add an optional note (e.g. “October commissions”) and click Create payout batch. Each affiliate gets one payout with all their approved commissions, minus their adjustments not deducted yet (the payout amount is the net amount). An affiliate needs at least one new commission and a net amount at or above the minimum to be included. The batch is a draft (“To pay”) until it is marked as paid; its commissions and adjustments are reserved and no longer appear as due.
  2. Open the batch and download the file for your payment method:
    • PayPal Payouts CSV – one line per PayPal payout, no header row, five columns: recipient PayPal email, net amount (e.g. 14.70), currency, a unique id (rz-<payout id>) and the note “Affiliate commission”. Payouts by another method or without a PayPal email are left out (the page says how many).
    • Bank transfers CSV – bank payouts only, with a header row: account name, account number / IBAN, bank code / BIC, bank name, country, net amount, currency, reference (“Commission <payout id>”), email. Use it for your bank's bulk upload (after mapping the columns) or as a checklist.
    • Full payout list – every payout with method, all details, net amount, currency, number of conversions, Adjustments (the deduction included in the amount, e.g. -14.70), status and reference, for accounting.
  3. Pay the affiliates (see the PayPal steps below, or your bank).
  4. Back in the batch, enter the payment reference (e.g. the PayPal batch id or the bank reference; affiliates see it), keep Email the affiliates on, and click Mark whole batch as paid. Or mark single payouts as paid (with their own reference), or Cancel payout for one affiliate: its commissions and adjustments become due again. A batch whose payouts are all cancelled is removed.

Marking a payout as paid changes its conversions to paid, emails the affiliate (when the program emails affiliates and SMTP is set up), notifies the merchant's channels (Payouts marked as paid) and shows the payout with its reference in the affiliate's portal.

Paying with PayPal Payouts

  1. You need a PayPal Business account with Payouts enabled. PayPal may have to approve the account for Payouts first (contact PayPal or apply in the PayPal dashboard); PayPal charges its own fees.
  2. Make sure the account has enough balance in the program's currency.
  3. Sign in to PayPal and open Pay & Get Paid → Payouts (in some regions Send payouts or Mass Pay).
  4. Choose to upload a file and select the PayPal Payouts CSV from Referzen. Choose “Email” as the recipient type if PayPal asks.
  5. Review the list (recipients, amounts, total, fees) and submit.
  6. Copy the batch id PayPal shows and paste it as the payment reference in Referzen, then mark the batch as paid.

Recipients without a PayPal account receive an email from PayPal to claim the money. Unclaimed payouts are returned by PayPal after a while; in that case cancel nothing in Referzen but settle it with the affiliate (e.g. ask for the correct PayPal email and pay again).

Integrations

This chapter is for you and your merchants; you can copy parts of it into your help pages. Every program's Integrations page (/dashboard/programs/<id>/integrations) shows the snippet with the right program key, the webhook URL, short guides for Stripe, WooCommerce, Shopify, other platforms and the REST API, and a test tool. A merchant needs two things:

  1. The tracking script on their website, so referral clicks are remembered.
  2. A conversion source: the program's webhook URL in Stripe, WooCommerce or Shopify, the generic webhook, or the REST API, so payments, refunds and disputes reach Referzen.
The webhook URL (https://partners.example.com/api/hooks/<token>) is secret: the long token in it identifies and authenticates the program. Anyone with the URL could send events, so keep it private. New URL on the Integrations page replaces it (update it everywhere afterwards). Each program has one URL for all sources: Referzen recognises Stripe, WooCommerce and Shopify by their headers and body. Add ?preset=stripe, woocommerce, shopify or generic to force one.

Signing secrets. Under Signing secret on the Integrations page a program can store up to 5 secrets, separated by commas or new lines (255 characters in total; each 8–200 characters, no spaces or commas): for example the Stripe test and live endpoint secrets, the Shopify key and a WooCommerce secret, or the old and the new secret while rotating. A signature made with any of them is accepted.

Once a secret is saved, every webhook must be signed (Stripe Stripe-Signature, X-WC-Webhook-Signature, X-Shopify-Hmac-Sha256 or X-Referzen-Signature for generic senders). A request without a signature is refused with 401, a wrong signature with 400. The only unsigned request accepted is WooCommerce's ping (webhook_id=…) sent when a webhook is saved; it records nothing. Without a secret, the secret token in the URL alone authenticates requests.

The tracking script

Paste this into the <head> of every page of the website (or the site-wide header template). The Integrations page shows it with the platform address and the program key:

<script async src="https://partners.example.com/rz.js" data-program="PROGRAM_KEY"></script>

That's all. Open the test link on the Integrations page (a page of the website with ?ref= and an affiliate code): the first click marks the program as Installation verified, and the dashboard shows Receiving referral clicks.

What the script does

  • On a page whose address contains ?ref=CODE (or ?via=CODE, or a data-param), it sends the click to /api/click. If the code belongs to an approved affiliate, it stores the returned referral token in the first-party cookie rz_ref (path /, SameSite=Lax, Secure on HTTPS, lifetime = the program's cookie duration) and a copy in localStorage that restores the cookie if it is deleted early. Optional ?sub= or ?sub_id= values are saved as the click's campaign (sub id). The page address is left as it is.
  • Visitors who did not come from an affiliate link get no cookie and send nothing.
  • On every page while the referral is valid, it hands the token to the checkout:
    • fills every <input name="referzen"> with the token, and adds that hidden input to forms marked <form data-referzen> (so it is posted with the form);
    • appends client_reference_id=<token> to links to Stripe Payment Links (https://buy.stripe.com/…);
    • on Shopify stores the token as the cart attribute referzen.
  • It is about 1.4 KB gzipped, loads asynchronously and catches all its own errors, so it can never break the page. Requests are sent without cookies or credentials.

Known bots, link previews and browser prefetches are filtered out on the server.

Stripe

Referzen reads Stripe's own events, so every Stripe setup works: Checkout, Payment Links, Billing subscriptions and custom PaymentIntents. Set it up once per program:

  1. Install the tracking script on the website (see above).
  2. Copy the webhook URL from the program's Integrations page.
  3. In the Stripe Dashboard open Developers → Webhooks and click Add endpoint (in the newer Workbench: Add destination → events from Your account → Webhook endpoint). Paste the URL as the endpoint URL.
  4. Select these events:
    EventUsed for
    checkout.session.completedPayments through Stripe Checkout and Payment Links (and the first payment of a subscription).
    checkout.session.async_payment_succeededOnly if you accept delayed payment methods (SEPA debit, bank transfers…).
    invoice.paidSubscription renewals (recurring commissions) and invoices.
    charge.refundedRefunds: reverses the commission when at least half of the payment was refunded.
    charge.dispute.createdDisputes / chargebacks: always reverses the commission.
    refund.created, refund.updatedOptional: the same refunds as Refund objects (only succeeded refunds count). Useful if your Stripe account sends refunds this way; when charge.refunded arrives as well, the second event is answered as a duplicate.
    payment_intent.succeeded or charge.succeededOptional: only if you charge without Checkout and put the token in the PaymentIntent's metadata (see below). Payments without that metadata are ignored.
    Other events are acknowledged with 200 and ignored, so selecting more does no harm.
  5. Save the endpoint, click Reveal under Signing secret and copy the value (whsec_…). In Referzen open the program's Integrations page → Signing secret, paste it and click Save secret. From then on only requests with a valid Stripe-Signature (at most 5 minutes old) are accepted, from Stripe and from every other source (see Signing secrets).
  6. Pass the referral to Stripe (next section).
  7. Test with Send a test event on the Integrations page, then with a real test payment (see Test events).
Test mode and live mode have separate webhook endpoints and separate signing secrets in Stripe. Save both whsec_… values in the program, separated by a comma (up to 5 secrets), so events from both endpoints are accepted.

Passing the referral token

The referral token is the value of the rz_ref cookie on the merchant's website, also available in the browser as referzen.referral. Stripe needs it in one of these fields (all are read):

Stripe objectField
Checkout Sessionclient_reference_id, or metadata.referzen
Payment Linkclient_reference_id in the link's address (added automatically by rz.js)
Subscription (created without Checkout)metadata.referzen (read from the invoices' subscription details)
PaymentIntent / Chargemetadata.referzen (needs payment_intent.succeeded or charge.succeeded)

The metadata keys referzen, _referzen, rz_ref and referral are all accepted.

Coupons. Stripe's events carry only coupon and promotion code ids, not the code the customer typed. To credit an affiliate's coupon code, put it in the metadata as coupon: metadata: { coupon: "JANE10" } on the Checkout Session, on a subscription created without Checkout (read from its invoices), or on the PaymentIntent. A promotion code is also read when the event contains it expanded (discounts[].promotion_code.code), which Stripe doesn't do in normal webhook deliveries.

Stripe Checkout (server code). Read the cookie on your server (it is sent with requests to the same site; for an API on another subdomain use data-domain=".acme.com"), or post referzen.referral from the browser together with your checkout request:

// Node.js
const session = await stripe.checkout.sessions.create({
  mode: "subscription",
  line_items: [{ price: "price_123", quantity: 1 }],
  client_reference_id: req.cookies.rz_ref, // or metadata: { referzen: req.cookies.rz_ref }
  success_url: "https://acme.com/thanks",
});
// PHP
$session = \Stripe\Checkout\Session::create([
  'mode' => 'payment',
  'line_items' => [['price' => 'price_123', 'quantity' => 1]],
  'client_reference_id' => $_COOKIE['rz_ref'] ?? null,
  'success_url' => 'https://acme.com/thanks',
]);

If client_reference_id is already used for something else, use metadata: { referzen: token } instead.

Stripe Payment Links. Nothing to do: rz.js adds client_reference_id to every buy.stripe.com link on pages where it runs. Buttons that open a Payment Link from JavaScript instead of a normal link need the parameter added by your own code.

Subscriptions (Stripe Billing). The first payment is recorded from checkout.session.completed; the matching first invoice.paid (billing reason subscription_create) is recognised and not counted twice. Every renewal invoice.paid is credited through the subscription id (or customer id) of the first payment and earns as long as the program's recurring rule allows it. A checkout with a free trial (nothing paid yet) records the customer as a lead; the first paid invoice after the trial becomes the conversion. If you create subscriptions without Checkout, put the token in the subscription's metadata.referzen, or record a lead with the customer id first (referzen.signup({ customerId: "cus_…" }) or POST /api/v1/referrals).

Payments without Checkout. Add metadata: { referzen: token } to the PaymentIntent and select payment_intent.succeeded. Charges and payment intents that belong to an invoice are left to invoice.paid.

Refunds and disputes. charge.refunded (or refund.created / refund.updated) reverses the commission when at least 50 % of the payment was refunded (smaller partial refunds keep it). charge.dispute.created always reverses it. Subscription payments are recorded under the invoice id, and Referzen also stores the invoice's payment intent and charge (payment_intent / charge on the invoice, or invoice.payments on newer Stripe API versions). Refunds and disputes are matched by the charge, the payment intent or the invoice, so first payments and renewals are both found. Only when none of these match, a refund falls back to the customer's latest payment of the same amount. A commission that was already paid out is reversed too and deducted from the affiliate's next payout (see Refunds after a payout).

WooCommerce

WooCommerce needs three things: the script, a small PHP snippet that saves the referral token in the order, and order webhooks.

  1. Add the tracking script to the store (WPCode, or the theme's header.php before </head>; see WordPress).
  2. Save the referral token in the order. The program's Integrations page (WooCommerce tab, step Save the referral in the order) shows this snippet ready to copy. Add it to the (child) theme's functions.php or with a code-snippets plugin such as WPCode (type “PHP snippet”, run everywhere). Leave out the first <?php line when pasting at the end of functions.php or into a snippet that already starts with it. It saves the visitor's rz_ref cookie as the order meta _referzen, for the classic checkout and the block-based checkout (WooCommerce 8.3+, the default in new stores): 
    <?php
// Referzen: remember the affiliate referral of the order (theme functions.php or a code snippets plugin).
function referzen_save_referral( $order ) {
    if ( ! empty( $_COOKIE['rz_ref'] ) && preg_match( '/^[A-Za-z0-9]{16,32}$/', $_COOKIE['rz_ref'] ) ) {
        $order->update_meta_data( '_referzen', sanitize_text_field( $_COOKIE['rz_ref'] ) );
    }
}
// Classic checkout.
add_action( 'woocommerce_checkout_create_order', 'referzen_save_referral' );
// Block checkout (WooCommerce 8.3+).
add_action( 'woocommerce_store_api_checkout_update_order_from_request', 'referzen_save_referral' );
    The order then shows a custom field _referzen, which is sent with the order webhook (meta_data).
  3. Create the webhooks: WooCommerce → Settings → Advanced → Webhooks → Add webhook:
    • Name: “Referzen”, Status: Active
    • Topic: Order created
    • Delivery URL: the program's webhook URL
    • Secret: the program's signing secret, if you save one (see below)
    • API version: WP REST API Integration v3
    Save, then add a second webhook with the topic Order updated and the same settings. WooCommerce sends an unsigned “ping” (webhook_id=…) when a webhook is saved; Referzen always accepts it and answers 200 (“WooCommerce ping received”).
  4. Signature (recommended): type any long secret in WooCommerce's Secret field of both webhooks and paste the same value in the program's Signing secret in Referzen (next to other secrets, separated by commas). Once a secret is saved, requests without X-WC-Webhook-Signature are refused with 401 and requests with a wrong one with 400 (see Signing secrets).
  • Orders are recorded when their status is processing or completed. Pending or on-hold orders are acknowledged and recorded once a later “Order updated” arrives with a paid status. Repeated deliveries of the same order never create a second conversion.
  • Refunded or cancelled orders, and refunds of at least half of the order, reverse the commission.
  • Orders without the token are credited by the billing email when that customer was recorded as a lead before (e.g. with referzen.signup() at registration), then by a coupon code of the order (coupon_lines) that the merchant assigned to an affiliate.
  • Later orders of the same registered customer (customer id), including WooCommerce Subscriptions renewal orders, count as renewals and earn according to the recurring rule. Guest orders have no customer id and always count as a first payment.
The order meta keys _referzen, referzen, rz_ref and referral are all accepted. Without the PHP snippet, orders carry no referral and are credited only through leads or coupons.

REST API

Plans with REST API can record sign-ups, conversions and refunds from their backend and read programs, conversions and affiliates. In the dashboard open API keys, enter a name and click Create key. The key (starting with rz_) is shown once; only a hash is stored. A key can access every program of the account. Up to 20 keys; Revoke deletes a key immediately; Last used shows when it was used.

Send the key in the Authorization header; send and receive JSON. Call the API from a server, never from browser JavaScript (that would expose the key). Amounts are in major units. The program_id is the number in the dashboard address of the program (/dashboard/programs/3), or the id from GET /api/v1/programs. Commissions are always in the program currency: a conversion in another currency carries commission_currency.

Method and pathBody / queryAnswer
GET /api/v1/programsnone{ data: [{ id, name, slug, currency, status, portal_url }] }, the programs of the key's account (read-only), oldest first

Attribution for POST /conversions follows the usual order: referral token, then affiliate_code, then the subscription / customer of an earlier conversion, then a lead with the same customer id or email, then the affiliate a coupon code belongs to. POST /conversions/refund reverses conversions recorded through the REST API, the generic webhook, the browser or by hand; provider conversions (Stripe, WooCommerce, Shopify) are reversed by the provider's own refund events. Write requests (POST) for a paused program, or a program whose owner is banned, answer 403.

Test events

The Integrations page has Send a test event: pick a sample (Stripe checkout, renewal, refund or dispute; WooCommerce order, refund or ping; Shopify order or refund; generic payment or refund). When the server can't reach its own public address (a local installation, a firewall or NAT, a wrong Site URL), the same sample is processed directly inside the app instead, and the answer starts with “Your server could not reach its own public address, so the event was processed directly.”

  • Plain samples carry a placeholder referral, so they are acknowledged with “No matching referral…” and nothing is recorded. This checks the URL, the signature and the parsing.
  • Use a real referral uses the latest referral click of an approved affiliate, so a real (test) commission is recorded. Click a referral link on the website first. Reverse the test conversion afterwards (reason “Test order”).

A complete end-to-end test: open https://acme.com/?ref=CODE in a private window, check in the browser's developer tools that the cookie rz_ref exists, make a test purchase (Stripe test mode, a WooCommerce test gateway, a Shopify test order) and watch it appear on the Conversions page within seconds. }
<script async src="/rz.js" data-program="PROGRAM_KEY" data-api="/rz"></script>

Next.js (next.config.js):

module.exports = {
  async rewrites() {
    return [
      { source: "/rz.js", destination: "https://partners.example.com/rz.js" },

import crypto from "node:crypto";
import express from "express";

const app = express();
app.post("/referzen", express.raw({ type: "application/json" }), (req, res) => {
  const expected = "sha256=" + crypto.createHmac("sha256", process.env.REFERZEN_SECRET).update(req.body).digest("hex");
  const given = req.get("X-Referzen-Signature") || "";
  const valid = given.length === expected.length && crypto.timingSafeEqual(Buffer.from(given), Buffer.from(expected));
  if (!valid) return res.status(401).send("Bad signature");
  const alert = JSON.parse(req.body.toString("utf8"));
  console.log(alert.event, alert.message);
  res.sendStatus(204);
});
app.listen(3000);

Privacy & cookies

Not legal advice. Affiliate tracking uses a cookie on the merchant's website. Rules differ by country (e.g. the GDPR and ePrivacy Directive in the EU and UK, CCPA in California). You are responsible for your platform (your Privacy policy, terms and any data processing agreement with merchants); merchants are responsible for informing their visitors and, where required, asking for consent. Ask a lawyer if in doubt.

The referral cookie on the merchant's website

  • rz.js sets the first-party cookie rz_ref (and a localStorage copy with the same name) on the merchant's domain, only for visitors who arrive through an affiliate link. It contains a random referral token and lasts for the program's cookie duration (default 60 days). On Shopify the token is also stored as a cart attribute (and a sessionStorage flag).
  • The platform's own domain sets no cookies for visitors; tracking requests are sent without cookies.
  • Merchants must mention the cookie in their cookie and privacy notice (name rz_ref, purpose: crediting affiliate referrals, duration: the cookie window, provider: their affiliate program on your platform). Where consent is required for this kind of cookie, they should load rz.js only after consent (most consent tools can hold back a script until the visitor agrees) and can add data-respect-dnt.

What is stored

  • Clicks: time, program, affiliate, referral token, landing page path (no query string), referrer hostname, campaign (sub id), country (only from hosting headers such as Vercel or Cloudflare), device type, a duplicate marker and an anonymous visitor hash: SHA-256 of a daily random salt, the IP address, the user agent and the program, shortened. The salt changes every UTC day and is deleted after two days, so the hash can't be turned back into an IP address or followed across days. IP addresses are not stored for clicks. Raw clicks are deleted after 90 days; daily totals are kept.
  • Leads and conversions: the customer's email (or only a hash of it, with Store a hash only), customer and subscription ids from the payment provider, order id, amount, currency and dates. Affiliates see customer emails masked (j•••@g•••.com).
  • Affiliates: name, email, scrypt password hash, website, payout details (PayPal email or bank account) and portal sessions (with IP address and user agent for security). The visitor hash of their portal sign-in is kept for the same device fraud check.
  • Your platform stores normal account data: names, emails, password hashes, payments, contact messages, and for signed-in sessions the IP address and user agent. It sets a session cookie for signed-in merchants and administrators, the portal cookie rz_aff for signed-in affiliates (scoped to their portal) and a language cookie. The cookie notice in Settings → Users is for your own site.

Merchants can delete affiliates (with their clicks, leads and unpaid commissions) or whole programs at any time. Review the default Privacy policy page and add your company details and the role of your platform as processor for merchants.

Adding a payment provider preset

To receive a provider's own webhooks (e.g. Paddle or Lemon Squeezy) without the generic format:

  1. src/lib/webhooks/presets.ts – add the name to WEBHOOK_PRESETS, recognise it in detectPreset() (a typical header such as x-paddle-signature, or the body shape), write a mapPaddle(body, headers) that returns { status: "ok", events } with ReferralEvents (kind payment / refund / lead; externalId unique per payment; amounts in minor units; the referral token from the provider's custom data; customerRef / subscriptionRef for renewals; couponCodes for coupon attribution; paymentRef / chargeRef when refunds or disputes arrive with other ids of the payment; relatedIds and paymentCents for refunds), or ignored / error, and add a case in mapWebhook().
  2. src/referral/types.ts – add the name to CONVERSION_SOURCES (up to 16 characters), and to SOURCES in src/lib/webhooks/receive.ts.
  3. src/lib/webhooks/verify.ts – a case in verifyWebhookSignature() for the provider's signature, checked against every saved secret (answer 401 when the header is missing, 400 when it doesn't match).
  4. src/lib/webhooks/samples.ts – a sample payload for Send a test event; the text dash.conv.source.<name> in messages.ts; optionally a guide tab on the Integrations page (src/app/(dashboard)/dashboard/programs/[id]/integrations/page.tsx).

Updating to a new version

  1. Back up the storage folder and your database.
  2. Replace all files except storage (and your .env file and your edited ecosystem.config.cjs, if any) with the new version.
  3. Run npm install and npm run build (this also rebuilds rz.js).
  4. Restart the app and the worker: pm2 restart all, docker compose up -d --build, or Restart in cPanel.

Database changes are applied automatically the first time the new version starts. Programs, program keys, webhook URLs, affiliates, links and API keys are kept: merchants don't need to change their snippets or webhooks. During the restart (usually a few seconds) clicks and webhooks can't be received; Stripe, WooCommerce and Shopify retry failed webhooks automatically.

Troubleshooting

Clicks are not recorded

Open the merchant's website with ?ref=CODE in a normal browser window (ad blocker off), press F12 and look at the Network and Console tabs. Filter by rz.js and click.

What you seeCause and solution
No request for rz.js at allThe snippet is not on the page (check the page source), the page comes from a cache that hasn't been cleared, or an optimisation plugin removed or delayed it. Clear caches; exclude rz.js from “delay JS” and combine features.
rz.js returns 404The platform hasn't been built with this version: run npm run build and restart. If you build on another computer, upload public/rz.js together with .next.
rz.js or the click request is “blocked” (ERR_BLOCKED_BY_CLIENT)An ad blocker or privacy extension. Test without it, or set up a first-party proxy.
Console: “Refused to load the script … Content Security Policy” or “Refused to connect”Add your platform to script-src and connect-src (see CSP).
No /api/click requestThe address has no ?ref= / ?via= (or the program uses other parameters: check data-param), the snippet has no data-program, or the browser sends Do Not Track and the snippet has data-respect-dnt.
/api/click answers 403 “This page is not on the program's website”Domain mismatch. The page's domain is not the program's website or a subdomain of it. Check the website in Program settings → General (without www), and add staging, shop or checkout domains under Other domains. For localhost switch on Count clicks from localhost.
404 with {"error":"Unknown program key."}The data-program key is wrong or was replaced with New key. Copy the snippet again.
404 {} (empty)The referral code doesn't exist in this program, or the affiliate is pending or blocked. Approve the affiliate.
403 “This program is paused” / “unavailable”The program is paused (resume it in Program settings, or in Admin → Programs), or the owner's account is banned (Admin → Users).
202 {}The request looked like a bot, a link preview or a prefetch (e.g. a headless browser or a testing tool). Test with a normal browser.
429More than 30 clicks per minute from one visitor (normal when you test by reloading a lot), or a proxy without X-Forwarded-For.
Mixed content errorThe website is HTTPS but the snippet uses http://. Install HTTPS on the platform and set the Site URL to https://.
Clicks counted but not “unique”The same visitor clicked the same affiliate's link again within 30 minutes: a duplicate click.

Conversions are not attributed

Look at the answer of the webhook first: Stripe (Developers → Webhooks → the endpoint → event deliveries), WooCommerce (Status → Logs, or the webhook's delivery log) and Shopify show Referzen's JSON answer, including a reason for ignored events. Or use Send a test event on the Integrations page.

Reason / symptomCause and solution
“No matching referral: no valid referral token…”The payment carries no referral token. Stripe: pass client_reference_id or metadata.referzen when creating the Checkout Session (see Stripe); Payment Links need rz.js on the page with the link. WooCommerce: add the PHP snippet (without it orders carry no referral). Shopify: check that the order has the referzen attribute (Order → Additional details). Also check that the buyer has the rz_ref cookie on the checkout domain (use data-domain across subdomains).
Outside the cookie windowThe click is older than the program's cookie duration at the time of the payment: not credited (as designed). Raise the cookie duration for future clicks.
“The referring affiliate (…) is pending / blocked, not approved.”Only approved affiliates earn. Approve the affiliate; for a missed sale add the conversion by hand.
"status": "duplicate"This order / invoice was already recorded (webhook retries, “Order created” + “Order updated”, or Stripe's checkout + first invoice). Nothing is wrong.
“Renewal outside the program's recurring commission period”The recurring rule doesn't cover this payment (first payment only, or N months have passed). Repeat orders of the same store customer count as renewals.
"rejected" / API 403 “monthly conversion limit”The merchant's plan reached its conversions per month. Upgrade, or wait for the 1st of the month (UTC).
“Order status … is not paid yet”WooCommerce: only processing and completed orders are recorded; the “Order updated” webhook records it once paid. Shopify: use the Order payment event.
403 “This program is paused” / “unavailable”Resume the program in Program settings (or Admin → Programs). “Unavailable” means the owner's account is banned. Stripe and Shopify retry the refused deliveries; in WooCommerce re-activate the webhook if it was disabled.
Conversion recorded twiceThe same order was reported through two sources (e.g. a Stripe webhook and the REST API). Use one source per order and reverse the extra conversion.
Coupon sale not creditedCheck the affiliate's Coupon code (any letter case matches) and that the code reaches Referzen: WooCommerce coupon_lines and Shopify discount_codes are read automatically; Stripe needs metadata.coupon; generic webhooks and the REST API need a coupon field. A coupon only counts when nothing earlier in the attribution order matched (e.g. another affiliate's referral cookie wins).
Conversion stays pending with “Repeat customer” or “Other currency”Flagged for review (see Fraud flags). Approve it by hand (for another currency, with a commission in the program currency) or reverse it.
Commission looks wrongA custom rate on the affiliate overrides the program's; renewals follow the recurring rule; changes apply to new conversions only; commissions are always in the program currency. The Conversions export shows payment number, amount and commission.
